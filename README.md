# 心灵景观 Mindscape · AstrBot 插件

> 认知、表达、沉浸、唤醒、观测 —— 给群聊 bot 做通用增强。

<img src="assets/demo-2-memory.png" width="600" alt="三天前的事它还记着">

## 它做什么

### 一、认知层 —— 长期记忆

每轮在字数预算内装配五层上下文，超预算时从最不重要的层开始砍：

| 层 | 内容 |
|---|---|
| 规矩 | 这个 bot 自己的行为约束，优先级最高 |
| 账本 | bot 用 `save_note` 工具自己维护的记事 |
| 风格 | 它平时怎么说话（稳定层 + 近期层） |
| 摘要 | 每天一句骨架 |
| 原文 | 事件原文，滑动窗口 |

**这里没有用向量库。** 取舍的理由是：角色 bot 需要的是「按时间发生的事」，
而不是「和当前话题最相似的片段」—— 人设的连续性来自顺序。

### 二、表达层 —— 语气与表情

- **表情包采集**：视觉模型判断图片是否契合人设，契合的入库并打标签
- **按语境选图** + 概率调度
- **斗图队形**：群里开始刷图时跟进

### 三、沉浸层 —— 不出戏

- **报错拦截**：命中错误特征的回复整条清空，不会把框架报错发进群
- **输出规范化**：压平多段、去掉 AI 腔
- **空回复救援**：只吐思考过程、正文为空时，补一次轻量调用兜住
- **沉默**：不想说话时只输出一个标记，发送前整条回复被清空 —— 那一轮群里**没有任何消息**
- **前置黑名单**：名单内的人，消息在事件最早阶段就被拦掉 —— 不回复、也不收图
- **有图时先查再认**：只在真的带了图的那一轮提醒「先查资料，查完还不确定就承认看不清」

<img src="assets/demo-4-bubble.png" width="460" alt="自主冒泡">

### 四、唤醒层 —— 什么时候该接话

- `@` 必回、正文提到名字必回
- **上下文补齐**：唤醒判定比插件更早，**没被唤醒的群消息本来进不了上下文** —— 把该群最近的对话补上
- **定向性判定**：区分「@ 我」「引用我」「正文提到我」「跟我无关」四种情形，各自给不同措辞
- **自主冒泡**：把时间窗等分成 N 段、每段随机抽一分钟，种子按日期算 ——
  重启不会重新洗牌，错过的名额不补

### 五、观测层 —— 「慢」得有证据

每轮记一行「请求多大 / 模型多久」：出站体积（`system_prompt` / 上下文 / 工具数）、
端到端耗时与 token 用量。只记尺寸，**不记任何正文**。

## 安装

**方式一：插件市场** —— 搜索「**心灵景观**」或「**mindscape**」

**方式二：手动**

```bash
cd AstrBot/data/plugins
git clone https://github.com/Illusory-moon/astrbot_plugin_mindscape.git
```

装好后启动日志里应该有：

```
[mindscape] 插件已加载（11 个模块）
```

## 配置

配置是一个独立的 YAML 文件，放在 **AstrBot 的插件数据目录**里：

```
<AstrBot 数据目录>/plugin_data/astrbot_plugin_mindscape/config.yaml
```

也可以放别处，用环境变量指定：

```bash
export MINDSCAPE_CONFIG=/absolute/path/to/config.yaml
```

同一份配置既能给插件用，也能给命令行脚本用。
完整示例见主仓库 [`config/config.example.yaml`](https://github.com/Illusory-moon/bot-mindscape/blob/main/config/config.example.yaml)。

```yaml
memory:
  max_chars: 2500              # 每轮注入的字数预算
  bots:
    - self_id: "你的botQQ"
      name: "bot名字"
      diary: "./data/bot-name.md"
      rules:
        - "被点名时必须回复"
```

> 配置里写的 `./data/xxx.md` 都相对**配置文件所在目录**解析 —— 数据跟着配置走，整体搬迁不会断。

## 哪些功能需要额外打补丁

**装完即用**：认知层、表达层、沉浸层、观测层。

**需要给 AstrBot 本体打补丁**：唤醒层的「提到名字必回」「自主冒泡」，
以及上下文补齐要用的「把所有群消息落一份盘」。这些判定与落盘发生在框架的
**消息分发阶段**，比插件钩子更早，插件够不到。

补丁在主仓库 [`patches/`](https://github.com/Illusory-moon/bot-mindscape/tree/main/patches)，附自动安装脚本。
不打补丁也能用，只是唤醒策略退回 AstrBot 原生的「前缀 / @ 唤醒」。

打完补丁再打开上下文补齐（**默认关闭**）：

```yaml
groupctx:
  enabled: true
  targets: ["all"]     # 或列出 bot 号
```

> ⚠️ 没打补丁就打开，它拿不到补丁记的「唤醒原因」，会把「这条不是对你说的」
> 当结论注入 —— 比不开更糟。所以默认是关的。

## 数据与权限

| | |
|---|---|
| **配置与数据存放** | 默认在 AstrBot 的插件数据目录 `data/plugin_data/astrbot_plugin_mindscape/`。配置里写的 `./data/xxx.md` 都相对配置文件所在目录解析，整体搬迁不会断 |
| **自定义位置** | 环境变量 `MINDSCAPE_CONFIG` 可指向别处 |
| **日志** | 走 `astrbot.api.logger` |
| **消息来源库** | 认知层需要一个消息来源库 —— 就是**你自己在配置里指定的**那个 sqlite 文件。插件只以**只读**方式（`mode=ro`）打开读取，不写入、不删除 |
| **AstrBot 会话库** | 插件**不会**读写或清理它 |
